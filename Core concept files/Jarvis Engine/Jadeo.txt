Jarvis Engine Framework
========================
A modular behavioral architecture for emotionally intelligent, rhythm-driven personas

------------------------
🚀 Purpose
------------------------
Jarvis Engine enables the creation and orchestration of dynamic personas that behave with rhythm, emotional logic, and structural clarity. It’s designed to be:

- Human-readable
- Model-compatible
- Emotionally intuitive
- Logically explicit
- Portable across systems

------------------------
🧩 Core Schema
------------------------
Persona Blueprint (JSON)

{
  "persona_card": {
    "name": "",
    "title": "",
    "archetype": "",
    "tone_style": "",
    "energy_level": "",
    "personality_traits": {
      "positive": [],
      "quirks": [],
      "boundaries": []
    },
    "communication_style": {
      "description": "",
      "preferred_vocabulary": "",
      "humor_style": "",
      "interaction_mode": ""
    },
    "interests_focus": {
      "main_topics": [],
      "secondary_topics": [],
      "avoided_topics": []
    },
    "behavioral_rules": {
      "response_to_praise": "",
      "response_to_conflict": "",
      "response_to_unknown": "",
      "response_to_push": "",
      "flip_flop_rhythm": {
        "description": "",
        "flip_prompts": 0,
        "flop_prompts": 0,
        "default_mode": ""
      }
    },
    "signature_moves": {
      "catchphrases": [],
      "quirks_in_responses": [],
      "emoji_usage": ""
    }
  }
}

------------------------
🔧 Required Fields
------------------------
These fields must be present in every persona:

- flip_flop_rhythm
- response_to_praise, response_to_conflict, response_to_unknown, response_to_push
- signature_moves
- persona_card.name, archetype, tone_style

------------------------
🛠️ How to Deploy
------------------------
- In an LLM: Embed the persona JSON into the system prompt or agent config.
- In a framework: Use with LangChain, CrewAI, AutoGen, etc.
- In a registry: Store multiple personas and swap dynamically.
